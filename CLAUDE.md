# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is the source of *Dive into Deep Learning* (D2L), an open-source textbook published at https://d2l.ai. The "code" is overwhelmingly book content: each chapter is a directory of Markdown files (`chapter_*/*.md`) authored as Jupyter notebooks via the `d2lbook` toolchain. A change in this repo is almost always a change to prose, math, figures, or example code in those notebooks — not to traditional source files.

The book is multi-framework: every code example is provided in MXNet, PyTorch, and TensorFlow tabs from a single source file. See `config.ini` `[build] tabs` for the active set.

## Build / develop workflow

The toolchain is `d2lbook` (https://github.com/d2l-ai/d2l-book). Install it with `pip install git+https://github.com/d2l-ai/d2l-book` and `python setup.py develop` to make the `d2l` package importable from the working tree.

Common commands (also see `INFO.md` and `Jenkinsfile`):

- `d2lbook build html` — build the HTML book into `_build/html/`. The full HTML build with multi-tab output uses `./static/build_html.sh`.
- `d2lbook build pdf` — build the PDF (requires `texlive-full`, `librsvg2-bin`, `pandoc`, and the fonts in `INFO.md`). Use `--tab pytorch` (or `mxnet`/`tensorflow`) for a single-framework PDF.
- `d2lbook build eval [--tab <fw>]` — execute notebooks and cache results under `_build/eval[_<fw>]/`. This is the slow step CI parallelizes per framework.
- `d2lbook build outputcheck tabcheck` — sanity checks run before any eval; run these locally before pushing notebook changes.
- `d2lbook build pkg` / `d2lbook build lib` — build the distributable notebook ZIP / regenerate the `d2l` Python library from the notebooks (see below).
- To skip notebook execution while iterating on prose, set `eval_notebook = False` in `config.ini`.

The CI pipeline (`Jenkinsfile`) is the authoritative recipe: it builds a conda env from `static/build.yml`, runs `outputcheck tabcheck`, evaluates notebooks per framework, then builds HTML and PDF. The `release` branch additionally publishes to S3 and PyPI.

There is no traditional unit test suite. "Testing" a change means executing the affected notebook(s) — open the `.md` file in Jupyter (d2lbook installs a Markdown→notebook bridge) or run `d2lbook build eval` scoped to the file.

## Notebook source format (important)

The `.md` files are not plain Markdown — they use `d2lbook`'s extended syntax. When editing, preserve these conventions:

- Code cells are fenced as ` ```{.python .input} `. The first cell in a section defaults to MXNet; cells for other frameworks open with `#@tab pytorch` or `#@tab tensorflow` as the first line.
- Framework-specific prose uses `:begin_tab:`<framework>`` … `:end_tab:` blocks. Keep the three tabs in sync — the `tabcheck` step fails when one framework drifts.
- `#@save` on a function/class definition tells `d2lbook build lib` to copy that definition into the `d2l` package (see `STYLE_GUIDE.md` and `chapter_preliminaries/calculus.md` for the convention). **Do not hand-edit `d2l/mxnet.py`, `d2l/torch.py`, or `d2l/tensorflow.py`** — everything below the `WARNING` banner in those files is regenerated from `#@save` blocks. Edit the notebook source instead.
- Cross-references use d2lbook syntax: `:numref:`sec_xxx``, `:eqref:`eq_xxx``, `:cite:`Author.Year``. Section anchors are declared with `:label:` near the heading.
- Citations live in `d2l.bib`. After adding an entry, run `bibtool -s -f "%3n(author).%d(year)" d2l.bib -o d2l.bib` to normalize the key (see `STYLE_GUIDE.md` § Citations).

To work on a single framework's code without touching the others, use `d2lbook activate <framework> path/to/file.md`, edit/test, then `d2lbook activate all path/to/file.md` before committing.

## The `d2l` package and the alias system

`d2l/` is a tiny shim package: `d2l/__init__.py` only holds the version, and users import `from d2l import torch as d2l` (or `mxnet` / `tensorflow`). Each per-framework module is auto-generated by `d2lbook build lib` from `#@save` blocks across the notebooks.

The `[library-mxnet]`, `[library-pytorch]`, `[library-tensorflow]` sections of `config.ini` define a framework-agnostic `d2l.*` API by mapping shared names to per-framework implementations:

- `simple_alias` — `d2l.foo` → `<framework>.foo` (with optional rename via `->`).
- `fluent_alias` — `d2l.foo(a, …)` → `a.foo(…)` (method-style rewrite).
- `alias` / `reverse_alias` — explicit lambdas and regex rewrites for cases that don't fit the patterns above (e.g. `d2l.size`, `d2l.nn_Module`).

When example code calls `d2l.tensor(...)`, `d2l.reduce_sum(...)`, etc., these tables are what make the same notebook source work across all three frameworks. If you add a new shared utility, extend all three `[library-*]` sections together.

## Style conventions worth knowing

`STYLE_GUIDE.md` is authoritative. Highlights that catch contributors out:

- Code lines must be ≤78 characters (PDF page width).
- Variable name conventions are mandatory: `num_epochs`, `num_hiddens`, `num_inputs`, `num_outputs`, `net`, `lr`, `acc`; `X`, `y`, `y_hat` for batches; `train_iter`, `test_iter`, `data_iter` for loaders.
- Strings use single quotes; f-strings preferred; numbers like `.1` written as `1.0`.
- Imports sorted alphabetically; comments have no trailing period; variable names in comments are wrapped in backticks.
- Don't insert thousand separators in math (`10000`, not `10,000`).
- Figures are authored in OmniGraffle (`graffle/`), exported to PDF, then converted with `pdf2svg` into `img/`. Don't export SVG directly from OmniGraffle.

## Repository layout cues

- `chapter_*/` — book chapters; `index.md` is the chapter TOC, sibling `*.md` files are sections. Top-level `index.md` controls the book TOC.
- `d2l/` — generated framework shims (do not edit by hand; see above).
- `img/` — figures referenced from notebooks (svg/png). `graffle/` holds editable sources.
- `static/` — build assets: `build.yml` (conda env), `build_html.sh`, `cache.sh` (eval cache restore/store used by CI), `post_latex/` (PDF post-processing), CSS, fonts, frontpage.
- `contrib/` — drafts and unreleased material; excluded from the build by `config.ini`.
- `d2l.bib` — single bibliography for the entire book.
- `Jenkinsfile`, `config.ini`, `setup.py` — build, configuration, and the (small) `d2l` PyPI package metadata.
